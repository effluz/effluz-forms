# Definitions Module and Manager Forms Pages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Staff can create forms, hold one draft per form edited through typed commands, publish immutable versions, run the lifecycle, edit operational settings, share a public link with a QR code, and read a form's activity, from the manager pages under `/admin/forms`.

**Architecture:** A new `definitions` module (domain, application, infrastructure, presentation) owning `form`, `form_draft`, `form_version` and `form_visit`. Drafts are `form-model` `Version` documents mutated only through a `DraftCommand` union applied in the domain, so keys, condition references and type changes are enforced in one place. Publishing copies the draft into an immutable version inside one unit of work. The manager shell and primitives live in `src/shared/presentation` so `review` can reuse them. Submission-dependent numbers come through a `SubmissionStats` port with a null adapter until the submissions module supplies the real one. The builder UI and translation suggestions are a later plan; a placeholder page holds the "Edit in builder" link.

**Tech Stack:** Next.js 16 (route handlers and server components, Cache Components on), React 19, TypeScript strict, Zod 4, `pg` with hand-written SQL, Vitest, `qrcode` (new, ADR 0021), pino.

**Spec:** `specs/use-cases/create-and-edit-form.md`, `specs/use-cases/publish-form.md`, `specs/use-cases/manage-form-settings.md`, `specs/form-definition.md` ("Concepts", "Text and languages", "Structure of a version", "Lifecycle", "Privacy rules enforced by the model"), `specs/ui-ux/manager.md` (Shell, Forms list, Form overview, Settings, Share, Activity, States, Fixed chrome copy), `specs/ui-ux/builder.md` ("New form" and its copy), `specs/architecture.md` (Modules, Ports, Publishing data flow), `specs/system/database.md`, `specs/system/security.md` ("Staff-authored content", "Audit log"), `design-system/`.

Decisions taken with the user before writing (2026-10-10): this plan covers the backend and the manager forms pages, not the builder UI or DeepL suggestions; draft edits are typed commands with a base revision; `qrcode` is added for PNG and SVG and the print PDF is deferred; the manager shell lives in `src/shared/presentation`; the form title joins the version structure and is mirrored on the form row; submission numbers come through a `SubmissionStats` port with a null adapter now.

## Global Constraints

- Layers: `domain` imports nothing outside itself and `src/shared/domain`; `application` only domain, its own ports and `src/shared/application` ports; `infrastructure` may import `pg`, Node and the module's inner layers; framework code only in `presentation/`, `src/app/` and `src/proxy.ts`. `definitions` may import only the public APIs of `form-model` (`@/modules/form-model/application`) and `identity` (`@/modules/identity/application`). ESLint `boundaries` enforces this; `pnpm lint` must pass.
- Slugs: lowercase letters, digits and hyphens, 3 to 64 characters, unique, never reused after a form is archived; reserved: `admin`, `api`, `health`, `f`.
- Keys: generated by the system, never typed; `/^[a-z][a-z0-9_]{3,31}$/` (`form-model` `keySchema`).
- System maximums (`form-model` `LIMITS`): pages per form 20; input fields per page 15, warn at 7; options per choice field 50; retention 1 to 36 months, default 12.
- Reference prefix: 2 to 6 uppercase letters or digits, default derived from the slug, read-only after the first submission.
- Notification recipients: addresses on the Workspace hosted domain or in `NOTIFICATION_ALLOWED_DOMAINS`.
- Default time zone `America/Panama`; dates stored in UTC and shown in both the form's zone and UTC.
- Audit entries: `form_created`, `draft_saved` (coalesced to one entry per editor per five minutes), `draft_language_mode_changed`, `form_published` (with version number), `form_closed`, `form_reopened`, `form_archived`, `form_unarchived`, `form_deleted`, `form_settings_changed` (with changed keys), `retention_shortened` (with the affected count). `details` never carry an address; `targetId` is the form id.
- Versions are immutable: a database trigger rejects `UPDATE` and `DELETE` on `form_version`.
- Every user-facing string of the manager comes from the copy tables in `specs/ui-ux/manager.md` and the "New form" table in `specs/ui-ux/builder.md`, bound in `copy.ts` files whose tests compare them to the spec rows. Pages render English with the Spanish line beneath (`lang="es"`) until a language preference exists.
- WCAG 2.2 AA: one `<h1>` and one `<main>` per page, breadcrumb from Forms downward, 44 px targets, visible focus, tables with headers, dialogs with a labelled heading, status badges with text. Design values from `design-system/tokens.json` only.
- Privacy: no answers, addresses or document contents in logs; logs carry form, draft, version ids and counts. Synthetic data only in tests and fixtures.
- Specs ship with the code: `specs/form-definition.md` (title), `specs/architecture.md` (ports), `specs/system/database.md` (tables), `specs/system/security.md` (audit actions), `specs/ui-ux/manager.md` (interim copy) and ADR 0021 are updated in the tasks that change behavior.
- TypeScript strict with `exactOptionalPropertyTypes` and `noUncheckedIndexedAccess`; Conventional Commits scoped `definitions`, `form-model`, `identity`, `shared`, `app`; Prettier via `pnpm format:check`.

## Review Focus

1. Two forms created at once with the same slug: one must get `slug_taken`, never a 500 (Task 8 integration test on the unique index).
2. Two publishes of the same form at once: the second must get `conflict` on the `(form_id, number)` unique constraint and the draft must stay intact (Task 10 integration test).
3. A draft command that moves a field above a field its condition references, or deletes a field another condition references, must be refused with the referencing keys (Task 5 unit tests).
4. A slug of an archived form must stay taken, and a form that has ever been published must refuse a slug change (Task 8 and Task 12 tests).
5. Lifecycle actions from the wrong status (close a draft, reopen a published form, unarchive a closed form) must be refused with `invalid_transition` and write no audit entry (Task 11 tests).

```ts
  | "invalid_document" | "bad_index";

export type CommandResult = { ok: true; document: Version; createdKey?: Key } | { ok: false; rejection: CommandRejection };
export const COMPATIBLE_TYPE_CHANGES: ReadonlyArray<readonly [FieldTypeId, FieldTypeId]> = [["short_text", "long_text"]];

export function applyCommands(document: Version, commands: readonly DraftCommand[], deps): { ok: true; document: Version; createdKeys: Key[] } | { ok: false; index: number; rejection: CommandRejection };
```

Rules every implementer must keep:
- The input document is never mutated; each command builds a new document and runs it through `parseDraft(next, registry)`; a parse failure returns `invalid_document` with the issues.
- `add_field` creates `{ key: newKey("f"), type, label: {}, required: false, personal: false, validation: [], settings: registry.get(type).defaultSettings ?? {} }` (read what the registry exposes for defaults; if there is no default-settings hook, use `{}` and let `parseDraft` apply the type's schema defaults; record which in the report). `limit_fields` when the page already has `LIMITS.inputFieldsPerPage` input fields and the new type is an input. `limit_pages` at `LIMITS.pagesPerForm`.
- `delete_field` and `delete_page` are refused with `referenced_by_conditions` listing `params.keys` (comma-joined referencing field and page keys) when any other field's or page's `visibility` references a deleted key (`referencedKeys` from `form-model`).
- `delete_page` on the only page is `last_page`.
